# Сценарии проверки

Каждая переведённая учётная система должна пройти S1–S8. Сначала на тестовой кассе, затем на настоящей кассе Pospoint с тестовым ФМ.

Тестовая касса: `MOCK=http://127.0.0.1:6461` (или порт из `--port`), ключ `mock-kassa-key`, экран кассира `$MOCK/`. Если учётная система работает на другом компьютере (например, сервер 1С в клиент-серверной базе), запустите тестовую кассу с `--host 0.0.0.0`: она напечатает адрес в сети для настроек учётной системы. Действия кассира — вызовы управления:

```sh
curl -s "$MOCK/mock/state"                                                   # окно кассы, «Предчеки», оформленные
curl -s -X POST "$MOCK/mock/issue"  -d '{"payCheckNumber":"<номер>"}'         # оформить
curl -s -X POST "$MOCK/mock/issue"  -d '{"payCheckNumber":"<номер>","changes":{"items":[{"sku":"<sku>","amount":1}],"payments":[{"type":"CARD","amount":15000}]}}'
curl -s -X POST "$MOCK/mock/reject" -d '{"payCheckNumber":"<номер>"}'         # отклонить
curl -s -X POST "$MOCK/mock/touch"  -d '{"payCheckNumber":"<номер>"}'         # кассир начал работу: без ограничения времени
curl -s -X POST "$MOCK/mock/park"   -d '{"payCheckNumber":"<номер>"}'         # «В Предчеки»
curl -s -X POST "$MOCK/mock/reset"                                           # очистить кассу
```

Действие кассира выполняйте, когда предчек виден в `$MOCK/mock/state` (`open`). Чтобы не ждать 90 секунд в S3, запустите тестовую кассу с `--idle-seconds 5`.

| Id | Учётная система | Кассир | Ожидаемый результат |
|---|---|---|---|
| S1 | Продажа: `sendPreReceipt` со своим номером документа и оплатой | `issue` | `ISSUED`, `changed: false`; учётная система сохранила состав и оплату |
| S2 | Продажа без оплаты, 2 единицы | `issue` с `changes`: 1 единица, `CARD` | `ISSUED`, `changed: true`, 1 единица, оплата `CARD`; учётная система учла изменённый состав |
| S3 | Продажа | ничего (ждать `--idle-seconds`), затем `issue` | Вызов завершился `14827`; учётная система не упала, спросила `getPreReceiptStatus` и получила `ISSUED` |
| S4 | Продажа | `reject` | `14828`; пользователь видит «отклонён кассиром»; исправленный предчек с тем же номером принимается |
| S5 | Повтор оформленной продажи с тем же номером | — | `14824`; второго чека нет, учётная система считает документ оформленным |
| S6 | Возврат 1 из 2 единиц по `sku` после S1 | `issue` | `ISSUED`, `type: REFUND`, 1 единица с тем же `sku` |
| S7 | Второй возврат больше остатка | — | `14807`; учётная система показывает ошибку и не считает возврат сделанным |
| S8 | — | — | В коде нет вызовов `registerSale`, `registerSaleFull`, `registerRefund`, `registerRefundFull`, `getReceipt`, `getReceiptByPayCheckNumber` и чтения `fmNo`, `kkmNo`, `shiftNumber`, `url`, `fiscalSign` из ответов кассы |

На настоящей кассе вместо вызовов управления действует кассир: «Оформить», изменение количества и способа оплаты, «Отклонить», «В Предчеки».
