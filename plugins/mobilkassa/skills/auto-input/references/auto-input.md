# Автоввод данных чека: методы порта 6461

Версия протокола 1.0.2. Учётная система (ERP) передаёт в кассу Mobilkassa предчек — данные будущего чека. Кассир проверяет предчек, при необходимости меняет его и оформляет. Касса формирует фискальный чек, печатает его и отправляет в ОФД. Учётная система получает статус и итоговый состав чека, но не фискальные данные.

## Что меняется 1 декабря

С 1 декабря 2026 года касса больше не оформляет чеки по прямым вызовам учётной системы.

| Метод | Что происходит |
|---|---|
| `registerSale`, `registerSaleFull` | Перенаправляется в предчек, если для организации установлен режим `ext-ser-mode = redirect`. Иначе ответ `-32601` «Method not found». |
| `registerRefund`, `registerRefundFull` | Так же: предчек возврата в режиме `redirect`, иначе `-32601`. |
| `getReceipt`, `getReceiptByPayCheckNumber` | Всегда `-32601`: фискальные данные чека не покидают кассу. |

В режиме `redirect` перенаправленный вызов отвечает в прежнем формате, но только после того, как кассир оформит чек, и без фискальных данных: `fmNo`, `kkmNo`, `shiftNumber`, `url` и `fiscalSign` приходят пустыми (`null`). Поля `id` и `time` заполнены; для возврата передавайте этот `id` в `idRefundReceipt`. Каждая позиция `registerSale` и `registerSaleFull` в этом режиме должна содержать `sku` — код позиции в учётной системе; позиция без него — ошибка `14804`. Режим `redirect` — временная мера на время перехода: он принимает и старые вызовы (с `sku`), и новые методы.

Без изменений работают: `checkFmStatus`, `checkFmCapacity`, `getFmInfo`, `syncFmState`, `syncWithOfd`, `openZReport`, `getXReport`, `closeZReport`, `validateMarkCode`, `validateReceiptMarkCodes`, `validateMxikPackages`, `getMxikInfo`.

## Как включить на кассе

- Автоввод работает только на кассе Retail. На кассе HoReCa режим всегда выключен.
- Настройки → Кассовый режим → переключатель «Автоввод данных чека». Изменение действует сразу, без перезапуска.
- Пока переключатель включён, блок показывает адрес с портом и ключ кассы для порта 6461. Ключ скрыт: «Показать» открывает его, «Копировать» копирует.
- С включённым автовводом касса всегда работает в фискальном режиме. При включении автоввода касса включает автопечать чеков; кассир может выключить её в настройках принтера.
- С выключенным автовводом новые методы отвечают `-32601`.

## Запрос и ответ

Запрос: `POST http://<адрес кассы>:6461/pospoint`, тело — JSON в UTF-8, не больше 2 МБ (2 097 152 байта). Проверка доступности: `GET /health` отвечает `{"status":"UP"}`.

```json
{
  "id": "1",
  "key": "<ключ кассы из настроек>",
  "version": "1.0.2",
  "method": "sendPreReceipt",
  "params": { }
}
```

- `id` — строка из цифр (число тоже принимается). В ответе `id` приходит числом.
- `key` — ключ кассы из блока «Автоввод данных чека».
- `version` — `1.0.2`.

Ответ содержит `result` при успехе или массив `error`:

```json
{"id": 1, "result": {"payCheckNumber": "INV-000123", "status": "ISSUED"}}
{"id": 1, "error": [{"code": 14804, "message": "JSON_REQUIRED_FIELDS_NOT_FOUND"}]}
```

Касса проверяет запрос в таком порядке и отвечает первой найденной ошибкой:

1. Тело — JSON, в нём есть `method`, `key`, `id` и `version`, иначе `-32700` «Parse error». Тело больше 2 МБ — `-32600` «Request too large».
2. Ключ, иначе `14800`.
3. `id` — число, иначе `14822`.
4. `version` из трёх целых чисел, иначе `-32602` «Invalid params (…)». Версия новее 1.0.2 хотя бы в одной части — `14801`.
5. Поля `params` (ниже). Здесь может прийти сразу несколько кодов.
6. Метод существует в этом режиме, иначе `-32601` «Method not found».

Ответ на ошибку пунктов 2–5 приходит с `"id": 0`, ответ на ошибку разбора — без `id`: касса читает `id` запроса только после этих проверок. Ошибки, которые возвращает сам метод (`14824`, `14827`, `14828`, `14829` и другие), и `-32601` приходят с `id` запроса.

## sendPreReceipt

Передаёт предчек продажи. Вызов удерживается, пока кассир не оформит или не отклонит предчек (см. «Удержание вызова»).

Поля `params`:

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `payCheckNumber` | строка | да | Номер документа учётной системы. Нет — `14804`. |
| `type` | строка | да | `SALE`, `ADVANCE` или `CREDIT`. Другое или нет — `14808`. |
| `items` | массив | да | Позиции, описание ниже. Пустой — `14810`. |
| `byCash` | число | нет | Сумма наличными. |
| `byCard` | число | нет | Сумма картой. Если оплата передана, `byCash + byCard` равно итогу ±50 сум, иначе `14807`. Отрицательная сумма — `14805`. Без оплаты способ выбирает кассир. |
| `discount` | число | нет | Скидка на весь чек. Отрицательная — `14806`. |
| `cardType` | число | нет | `0` не указана, `1` корпоративная, `2` личная, `3` социальная. Для `3` нужны `rrn` и `socialCardNumber`, иначе `14823`. |
| `rrn`, `socialCardNumber` | строка | для `cardType` 3 | Данные социальной карты. |
| `phoneNumber` | строка | нет | Телефон покупателя. |
| `mkDetailed` | логическое | нет | Подробные ошибки по кодам маркировки. |
| `markValidationSkip` | логическое | нет | Пропустить онлайн-проверку кодов маркировки. |

Поля позиции (`items[]`) — те же, что у `registerSaleFull`, плюс обязательный `sku`:

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `name` | строка | да | Название. |
| `amount` | число | да | Количество, больше 0, иначе `14813`. |
| `price` | число | да | Цена за единицу, больше 0, иначе `14812`. |
| `mxik` | строка | да | ИКПУ (MXIK). |
| `ownerType` | число | да | Тип владельца товара. |
| `unit` | строка | да | Код единицы измерения. |
| `packageCode` | число | да | Код упаковки. |
| `taxPercent` | число | да | Ставка НДС: `0`, `6` или `12`, иначе `14814`. |
| `sku` | строка | да | Код позиции в учётной системе, до 64 знаков, иначе `14818`. Нет или пустой — `14804`. Возвращается в результате и называет строку при возврате. |
| `mkCode` | массив строк | нет | Коды маркировки: каждый не короче 18 знаков; один на строку или по одному на единицу, иначе `14817`. |
| `discount` | число | нет | Скидка на позицию, от 0 до суммы позиции, иначе `14815`. |
| `barcode` | строка | нет | Штрихкод. |
| `comTin` | строка | нет | ИНН или ПИНФЛ комитента: 9 или 17 знаков, иначе `14816`. |
| `recipeId` | строка | нет | Номер рецепта. |

Без любого из обязательных полей позиции, в том числе без `sku`, касса отвечает только `14804`. Числа передавайте числами JSON, не строками.

До того как кассир увидит предчек, касса проверяет его так же, как прежний путь чека: формат полей, ИКПУ по каталогу tasnif (`14825`), повтор документа (`14824`), состояние кассы (`-10`, `-14`, `-555`), продажа за наличные по УП-246 (`-15`), коды маркировки (`14823`, `14826`). Ошибки `14823`, `14825` и `14826` могут нести поле `data` с подробностями. Ошибка приходит сразу, и предчек не сохраняется.

## Результат

Каждый ответ `sendPreReceipt`, `sendRefundPreReceipt` и `getPreReceiptStatus` содержит `payCheckNumber` и `status`:

- `WAITING` — предчек ждёт кассира (в окне кассы или в «Предчеках»);
- `ISSUED` — чек оформлен;
- `REJECTED` — кассир отклонил предчек.

Для `ISSUED` также приходят:

| Поле | Что значит |
|---|---|
| `type` | `SALE`, `ADVANCE`, `CREDIT` или `REFUND`. |
| `changed` | `true`, если кассир изменил предчек: уменьшил количество, убрал позицию или принял оплату другим способом. |
| `items[]` | Итоговые позиции: `sku`, `name`, `amount`, `price`, `discount`, `sum`. |
| `payments[]` | Оплата: `type` (`CASH`, `CARD`, `ONLINE` — QR-оплата, `DEBT` — в долг) и `amount`. |
| `total` | Итог чека. |

```json
{
  "payCheckNumber": "INV-000123",
  "status": "ISSUED",
  "type": "SALE",
  "changed": false,
  "items": [{"sku": "2050", "name": "Чай чёрный 100 г", "amount": 2.0, "price": 15000.0, "discount": 0.0, "sum": 30000.0}],
  "payments": [{"type": "CASH", "amount": 30000.0}],
  "total": 30000.0
}
```

В ответах нет и не будет фискальных данных: номера чека, номера ФМ (`fmNo`), номера ККМ (`kkmNo`), номера смены (`shiftNumber`), времени фискального чека, ссылки на чек с QR-кодом (`url`) и фискального признака (`fiscalSign`). Чек печатает касса. Если учётная система печатает QR-код или хранит фискальный признак, этот код нужно убрать.

## Удержание вызова

Вызов `sendPreReceipt` и `sendRefundPreReceipt` удерживается, пока кассир не оформит или не отклонит предчек.

- Кассир 90 секунд ничего не делает с предчеком — вызов завершается ошибкой `14827` «ожидает кассира». Предчек не отменяется и ждёт в «Предчеках».
- Предчек раньше ушёл в «Предчеки» (пришёл следующий предчек, кассир нажал «В Предчеки», кассир занят другой продажей) — `14827` сразу.
- Если кассир начал работать с предчеком, вызов ждёт результата без ограничения времени.
- Другие запросы к порту 6461 обслуживаются, пока вызов удерживается.

Что делать учётной системе: ставить таймаут HTTP больше 90 секунд (рекомендуем 120). При таймауте или `14827` спрашивать результат через `getPreReceiptStatus` по номеру документа, например каждые 5 секунд.

## getPreReceiptStatus

Возвращает состояние предчека по номеру документа.

```json
{"id": "2", "key": "<ключ>", "version": "1.0.2", "method": "getPreReceiptStatus", "params": {"payCheckNumber": "INV-000123"}}
```

- `WAITING` — ждёт кассира;
- `ISSUED` — с полным составом, как в «Результат»;
- `REJECTED` — отклонён;
- неизвестный номер — `14829`; без `payCheckNumber` — `14804`.

## Повторы и отклонение

Повтор с тем же `payCheckNumber` не создаёт второго предчека и второго чека:

- предчек открыт в окне кассы — повтор ждёт того же результата;
- предчек в «Предчеках» — сразу `14827`, предчек остаётся там;
- чек уже оформлен или чек с этим номером существует — `14824`. Если это ваш предчек, `getPreReceiptStatus` по тому же номеру вернёт `ISSUED` с составом: считайте документ оформленным, а не ошибочным;
- предчек отклонён — повтор принимается как новый предчек с новым содержимым.

Кассир нажал «Отклонить» — удерживаемый вызов получает `14828`, `getPreReceiptStatus` отвечает `REJECTED`. Исправленный предчек можно отправить с тем же номером.

Всегда передавайте свой номер документа: только он делает повтор безопасным.

## sendRefundPreReceipt

Передаёт предчек возврата. Касса сама находит чек продажи.

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `payCheckNumber` | строка | да | Номер документа возврата. |
| `salePayCheckNumber` | строка | одно из двух | Номер документа продажи. |
| `saleId` | число | одно из двух | Номер чека кассы — бывший `idRefundReceipt` из `registerRefund`. Для продажи без номера документа. |
| `items` | массив | нет | Без `items` возвращается весь остаток продажи. Пустой массив — `14810`. |
| `byCash`, `byCard` | число | нет | Сверяются с суммой возврата (`14807`), но не задают способ оплаты: его выбирает кассир. |

Позиция возврата (`items[]`): `amount` (больше 0, иначе `14813`) и то, что называет строку продажи. Касса ищет строку в таком порядке:

1. `sku` — для продажи, пришедшей предчеком с `sku`;
2. `uid` — код позиции кассы, как в `registerRefund`;
3. `mxik` или `barcode`; если таких строк несколько — строка с тем же `name`;
4. `name`.

`mkCode` (необязательно) — коды маркировки возвращаемых единиц: один на строку или по одному на единицу, иначе `14817`. Без `mkCode` касса сама выбирает ещё не возвращённые единицы.

Ошибки:

- продажа не найдена — `14829`;
- позиция ничего не называет — `14804`;
- позиция не нашлась в продаже — `14811`;
- возврат больше остатка — `14807`. Остаток уменьшают оформленные возвраты и ожидающие предчеки возврата.

Кассир может уменьшить возврат или убрать строку, но не увеличить. Ответ `ISSUED` приходит с `type` `REFUND` и перечисляет фактически возвращённые строки, каждую со своим `sku`. `changed` — `true`, если возврат уменьшен или оплачен другим способом. Невозвращённое можно запросить следующим предчеком возврата.

## Старые методы → новые

| Было | Стало |
|---|---|
| `registerSale`, `registerSaleFull` | `sendPreReceipt` с `type` `SALE`, `ADVANCE` или `CREDIT`. Позиции — те же поля, что у `registerSaleFull`, плюс обязательный `sku`. |
| `registerRefund`, `registerRefundFull` | `sendRefundPreReceipt`. Продажу называет `salePayCheckNumber` или `saleId` (бывший `idRefundReceipt`). |
| `getReceipt`, `getReceiptByPayCheckNumber` | `getPreReceiptStatus` по номеру документа. Фискальных данных в ответе нет. |
| Чтение `fmNo`, `kkmNo`, `shiftNumber`, `url`, `fiscalSign` | Убрать: чек печатает касса, фискальные данные остаются в ней. |
| Таймаут HTTP 30–60 секунд | Больше 90 секунд, плюс `getPreReceiptStatus` после таймаута. |

## Шаблон клиента

1. Соберите предчек со своим `payCheckNumber` и `sku` у каждой позиции.
2. Отправьте `sendPreReceipt` с таймаутом HTTP 120 секунд.
3. `ISSUED` — сохраните итоговый состав и оплату из ответа.
4. `14827` или таймаут — предчек ждёт кассира. Спрашивайте `getPreReceiptStatus` каждые 5 секунд или покажите пользователю, что чек оформляет кассир. Повторная отправка с тем же номером безопасна.
5. `14828` — покажите «отклонён кассиром» и дайте отправить исправленный предчек с тем же номером.
6. `14824` при повторной отправке — документ уже оформлен (ответ потерялся или учётная система перезапустилась). Спросите `getPreReceiptStatus`: `ISSUED` — сохраните состав и не пробивайте чек второй раз.
